# Feedback — unico punto di raccolta su GitHub

Tutto il feedback dell'add-on **Auto Copy Transforms DEF** (bug, idee, test di
compatibilità, domande) viene raccolto in **un solo posto**: GitHub. L'obiettivo
è che l'utente trovi tutto lì dentro, senza dover cercare su altri canali.

## Unica fonte dei feedback

**<https://github.com/PieroFra/auto-copy-transforms-def/issues>**

Le GitHub Discussions **non** sono attive su questo repo
(`hasDiscussionsEnabled=false`): l'unico punto naturale e sempre aperto sono le
**GitHub Issues**, con i template già creati `bug_report.yml`,
`feature_request.yml` e `compatibility.yml` (cartella `.github/ISSUE_TEMPLATE/`).

## Come smistare i feedback per categoria

- **Bug/errori** -> nuova Issue con template **Bug report** (`bug_report.yml`).
- **Test su altre versioni di Blender (4.2-5.1)** -> template **Compatibility
  report** (`compatibility.yml`).
- **Idee/miglioramenti** -> template **Feature request** (`feature_request.yml`).
- **Domande/workflow/rigging** -> Issue normale con label `question`
  (in futuro, se attivate, GitHub Discussions).

## Come gestire feedback arrivati su altri canali

Blender Artists, Reddit, commenti ai video, Blender Extensions, ecc. **non** sono
punti di raccolta: tutto va riversato su GitHub Issues. Procedura per l'autore
in 3 passi:

1. **Ringrazia** l'utente e incolla il link alla issue/template per i dettagli
   (<https://github.com/PieroFra/auto-copy-transforms-def/issues>), invitandolo ad
   aprire la issue con il template giusto per la sua categoria.
2. **Se l'utente non la apre**, aprila tu stesso citando il canale d'origine
   (es. "segnalazione arrivata da Reddit r/blender il GG/MM/AAAA").
3. **Tagga la provenienza** con la label del canale: `from-reddit`,
   `from-blenderartists`, `from-extensions`.

## Elenco etichette consigliate

`bug` · `compatibility` · `enhancement` · `question` · `from-reddit` ·
`from-blenderartists` · `from-extensions`
